# MarketPlat — توحيد الكاش V2

## الحزم

- `marketplat-cache-unification-v2.zip`: تعديلات الكاش وحدها، وتُطبّق فوق نسخة المشروع التي سبق دمج حزمة توحيد الفلاتر فيها.
- `marketplat-complete-filters-and-cache-v2.zip`: حزمة تراكمية تُطبّق مباشرة فوق النسخة الأصلية المرفوعة؛ وتشمل توحيد الفلاتر السابق وتوحيد الكاش الحالي.

## طريقة الدمج

1. خذ نسخة احتياطية من المشروع أو أنشئ فرع Git جديداً.
2. فك ضغط الحزمة المناسبة داخل جذر المشروع مع السماح باستبدال الملفات.
3. من جذر المشروع شغّل `pnpm cache:sync` ثم `pnpm cache:layer-audit`.
4. شغّل فحوصات الويب والـ API والموبايل وCloudflare المتاحة في بيئتك.

## مصدر الحقيقة

- `shared/cache-policy.json`: مدد الصلاحية والاحتفاظ وحدود التخزين وسياسات React Query وRedis وSQLite وCloudflare.
- `shared/cache/cache-contract.json`: نطاقات الكاش، وقواعد الإبطال، ووسوم القراءة والكتابة، وقواعد إبطال تغييرات الموبايل.
- `shared/cache/cacheKey.ts`: خوارزمية هوية مفاتيح Redis/API المشتركة.

الملفات المولّدة في الويب والـ API والـ Service Worker والموبايل وCloudflare يجب ألا تعدّل يدوياً؛ عدّل المصدر المشترك ثم نفّذ `pnpm cache:sync`.

## التحقق المنفذ

اجتازت فحوصات المزامنة والتدقيق المركزي، وتدقيقات W1–W12، وفحوصات TypeScript المستهدفة لوحدات سياسة الكاش، وفحوصات بناء الصياغة لملفات الواجهة المعدّلة، و8 اختبارات تخزين للموبايل. لم يتم تشغيل build أو TypeScript الكامل أو ESLint أو Vitest للمشروع كله لأن الاعتماديات (`node_modules`) وأداة `pnpm` غير متوفرتين في بيئة الفحص.

## ملاحظات السلوك

تم الحفاظ على قيم الصلاحية الحالية، بما فيها كاش البيانات الشخصية والرسائل، مع نقلها إلى سياسة مشتركة. جرى رفع حدود مساحة Service Worker لتتطابق مع توقعات اختبارات الكاش الموجودة بالمستودع (من دون تغيير نطاق التخزين الخاص أو جعل البيانات الخاصة قابلة للتخزين العام).

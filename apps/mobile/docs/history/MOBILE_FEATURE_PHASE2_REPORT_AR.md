# تقرير ميزات الموبايل — الدفعة الثانية

## النطاق
أضيفت تجربة المحادثات والإشعارات داخل تطبيق React Native، باستخدام المسارات الموجودة في API دون تعديل الـ Backend.

## الملفات المضافة
- `app/messages.tsx`: قائمة المحادثات، معاينة آخر رسالة، اسم الطرف الآخر، مؤشر الرسائل غير المقروءة، التحديث بالسحب، وحالات التحميل/الخطأ/الفراغ.
- `app/messages/[id].tsx`: تفاصيل المحادثة، سجل الرسائل، إرسال نص حتى 2000 حرف، فقاعة متفائلة مؤقتة مع استرجاع النص عند فشل الإرسال، وتحديث يدوي.
- `app/notifications.tsx`: مركز الإشعارات، تمييز المقروء وغير المقروء، تعليم إشعار أو جميع الإشعارات كمقروءة، والتنقل للمحادثة عندما تتوفر هوية المحادثة في بيانات الإشعار.
- `src/features/messaging/messaging.api.ts`: طبقة API typed للمحادثات والرسائل والإشعارات وعدادات غير المقروء.
- `scripts/verify-feature-phase2.mjs`: فحوص ساكنة خاصة بالدفعة.

## ملفات معدلة
- `app/index.tsx`: إضافة مداخل الرسائل والإشعارات من الصفحة الرئيسية.
- `app/ads/[id].tsx`: إضافة إجراء مراسلة البائع وإنشاء/إعادة استخدام المحادثة من الخادم.
- `package.json`: إضافة فحوص الدفعة إلى سكربت الاختبارات الحالي.

## نقاط هندسية
- تعتمد المصادقة على `accessToken` من AuthContext.
- تُستخدم واجهات `GET/POST /api/v1/conversations` و`GET /api/v1/conversations/:id/messages` ومسارات `/api/v1/notifications` الموجودة.
- لا يتم ادعاء نجاح إرسال الرسالة قبل رد الخادم؛ الرسالة المتفائلة مؤقتة وتُحذف عند الفشل.
- قراءة الرسائل على الخادم تحدّث حالة القراءة بحسب تنفيذ conversations service الحالي.
- لم تتم إضافة WebSocket أو Push Notifications أصلية؛ هذه الدفعة تنفذ مركز الإشعارات داخل التطبيق وقائمة/تفاصيل الرسائل، أما التحديث الفوري وإعداد FCM/Expo Push فيحتاجان مرحلة مستقلة.

## التحقق
- فحوص الدفعة الأولى الساكنة: 5/5 ناجحة في بيئة العمل.
- يجب تشغيل `pnpm --filter @marketplat/mobile test` و`pnpm --filter @marketplat/mobile type-check` في بيئة المشروع المثبتة.
- محاولة `tsc --noEmit` في بيئة التدقيق الحالية لم تكتمل لغياب حزمة Expo (`expo/tsconfig.base`) ولأن نسخة TypeScript العامة لا تطابق خيار `ignoreDeprecations` في المشروع. لذلك لم يُدّعَ نجاح فحص الأنواع أو بناء APK.
- لم يتم اختبار الخادم الفعلي أو جهاز Android من هذه البيئة.

## تطبيق الدفعات
طبّق ZIP الدفعة الأولى أولًا، ثم ZIP الدفعة الثانية. يتضمن تعديل الصفحة الرئيسية في هذه الدفعة تغييراتها السابقة عند دمج الدفعة الأولى، لذلك لا تُعدّل `app/index.tsx` يدويًا فوق نسخة قديمة دون مقارنة.

# تقرير ميزة طلب المنتجات — MarketPlat Mobile + API

## النطاق

إضافة أول نسخة متكاملة لطلبات شراء المنتجات من متجر واحد في الطلب، مع الدفع عند الاستلام. هذه الميزة مستقلة عن `ServiceRequest` و`SaleRecord`: الأولى لطلب الخدمات من مقدم خدمة، والثانية دفتر مبيعات للتاجر بما فيها المبيعات النقدية خارج المنصة.

## ما تم إضافته

- نموذج Prisma `MarketplaceOrder` و`MarketplaceOrderItem` مع لقطات اسم المنتج وصورته وسعر الوحدة عند الشراء.
- ترحيل SQL لإنشاء الجداول والفهارس والعلاقات.
- API محمية بالمصادقة لإنشاء الطلبات، عرض طلبات المشتري، عرض طلبات التاجر، عرض التفاصيل، وتحديث الحالة.
- التحقق من أن كل منتجات الطلب من متجر واحد، وأن المتجر نشط وغير موقوف، ومنع الطلب من المتجر الخاص بالمشتري.
- حساب السعر في الخادم، وتثبيت السعر في عناصر الطلب، وحجز الكمية ضمن معاملة، مع فحص مخزون شرطي لمنع بيع كمية غير متاحة.
- مفتاح idempotency اختياري لإعادة المحاولة دون إنشاء طلب مكرر.
- انتقالات حالة محددة: `PENDING → CONFIRMED → PROCESSING → SHIPPED → DELIVERED`، مع الإلغاء ضمن الحالات المسموح بها فقط.
- واجهات الموبايل: إتمام الطلب، طلباتي، طلبات متجري، تفاصيل الطلب، وتحديث حالة الطلب.
- إضافة اختبارات تحقق ثابتة للميزة إلى `npm test` في تطبيق الموبايل.

## API

- `POST /api/v1/orders`
- `GET /api/v1/orders/mine?page=1&limit=20`
- `GET /api/v1/orders/seller?page=1&limit=20`
- `GET /api/v1/orders/:id`
- `PATCH /api/v1/orders/:id/status`

## افتراضات وحدود النسخة الأولى

- الدفع عند الاستلام فقط؛ لا يوجد تحصيل إلكتروني.
- الطلب الواحد لا يجمع منتجات من متاجر مختلفة.
- رسوم التوصيل ثابتة على صفر في هذه النسخة؛ يجب إضافة إعدادات شحن على مستوى المتجر قبل فرض أي رسوم مستقبلية.
- لا يوجد حتى الآن نظام شركات توصيل أو إشعارات push مخصصة للطلب.
- أسعار الطلب تُحسب من سعر المنتج وخصمه الثابت أو العرض النشط وقت الإنشاء، ولا تُؤخذ من السعر المرسل من الجهاز.

## التحقق

شُغّل اختبار التحقق الثابت `verify-feature-orders.mjs`. لم يُشغّل Prisma Client generation أو TypeScript build أو اختبارات تكامل بقاعدة بيانات فعلية في بيئة العمل الحالية؛ لذلك يجب تنفيذ هذه الخطوات بعد تثبيت تبعيات المشروع وقبل النشر.

## خطوات ما قبل النشر

1. شغّل ترحيل قاعدة البيانات من حزمة API باستخدام `prisma migrate deploy`.
2. أعد توليد Prisma Client (`prisma generate`).
3. نفّذ فحص TypeScript واختبارات API، ثم اختبر سيناريو شراء وإلغاء متزامن على قاعدة اختبار.
4. ابنِ APK واختبر تجربة المشتري والتاجر بحسابين مختلفين.

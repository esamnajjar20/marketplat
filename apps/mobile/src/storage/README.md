# Mobile storage layer

## Layout

| Area | Role |
|------|------|
| `encrypted-database.ts` | SQLCipher-backed opener |
| `public-cache.ts` / `public-image-cache.ts` | Offline read cache |
| `mutation-outbox.ts` | Ad create/update/delete queue |
| `entity-create-outbox.ts` | Product/service/sale offline creates |
| `order-outbox.ts` | Marketplace orders |
| `chat-message-outbox.ts` / `chat-media-outbox.ts` | Chat offline send |
| `ad-draft-store.ts` / `persist-ad-image.ts` | Local drafts & images |
| **`outbox-manager.ts`** | **Façade for queue APIs, counts and snapshot** |
| `outbox-sync*.ts` / `Outbox*LifecycleBridge.tsx` | Background sync bridges |

## Pure helpers and Node tests

Dependency-free helpers (`draft-operation-queue.ts`, `outbox-sync-policy.ts`, `outbox-transport-contract.ts`, `public-cache-policy.ts`, `public-image-cache-policy.ts`, `sqlcipher-key-policy.ts`) are plain `.ts` files with no `@/` aliases and only erasable TypeScript syntax. The app bundle and the Node tests (`__tests__/*.test.mts`, run with `node --test`, Node >= 22.18) import the same file. There are no `.mjs` / `.d.mts` mirrors.

## Guidance

- UI screens should import queue APIs from `outbox-manager` rather than directly from low-level queue modules. The façade exposes mutation, entity-create, order, chat message/media, request-create and request-offer queue APIs/types. Its snapshot includes all seven account-scoped queues and reports incomplete reads; destructive logout uses the stricter database-backed count in `public-cache.ts`.
- Workers / lifecycle bridges may use specific outbox modules for claim/ack/retry internals.
- Never convert a failed queue read into a zero pending count; surface the failed queue and block destructive logout when the count is unknown.
- Never run network I/O inside SQLite exclusive transactions.

### Pure queue helpers: single implementation

- The six helpers above are the single executable implementation of their logic; Node's test runner executes those exact files.
- Keep them free of `@/` imports and runtime-only TypeScript features (enums, parameter properties).

### Offline cache and native encryption limits

- The shared native SQLite database is opened only through `encrypted-database.ts`; SQLCipher is required and the key is a 256-bit random value stored in SecureStore. The opener validates key shape, authenticates the database, and runs `PRAGMA quick_check` before exposing the connection.
- Public API snapshots expire after 7 days; account-scoped `api-private:` snapshots expire after 24 hours. Explicit `saved_offline_resources` are separate user bookmarks and do not expire with the response cache.
- The public JSON cache is capped at 100 entries / 6 MB (UTF-8 payload estimate). The image cache targets 120 files / 80 MB with 5 MB per-image limit. Old unreferenced files are evicted first. Files referenced by either cache snapshots or explicit saved-offline records are pinned; if pinned content alone exceeds 80 MB, it is preserved rather than silently broken, so 80 MB is a target budget, not a hard cap.
- `cachePublicImages()` handles up to 8 images per call; an ads list caches at most 8 image URLs across the whole page, not 8 per card. It returns remote URLs when a download fails. Explicit save-offline filters those URLs out, saves at most 8 local images per resource, and reports partial image availability; it does not claim a remote-only image is stored offline.
- Public ad-list image downloads and cache pruning run after the API page is returned. Opportunistic list pruning is throttled to at most once every 15 minutes; explicit save/offline flows retain immediate pruning. Cloudinary list images are downloaded as 480px thumbnails, not as full-resolution originals.
- SQLCipher encrypts SQLite databases only. Downloaded image/media files remain ordinary files in the app-private sandbox; they are not SQLCipher-encrypted. Android backup rules exclude the private database, SecureStore preferences, and app files, and are generated by `plugins/with-secure-storage-backup.js` so `expo prebuild --clean` retains them. iOS backup exclusion and device-level validation remain release checks.
- Pure dependency-free policy helpers (plain `.ts`, see above) are canonical runtime modules and are tested directly with Node's built-in test runner. They are not merely generated test mirrors.

# تقرير تنفيذ إصلاحات MarketPlat Mobile

**التاريخ:** 29 أكتوبر 2026  
**النطاق:** تطبيق `apps/mobile`، إعدادات monorepo ذات الصلة، وفحوص GitHub Actions.  
**المنهج:** تنفيذ الإصلاحات التي تدعمها الملفات وعقود الكود الحالية؛ فصل ما تحقق ساكنًا عن ما يحتاج تثبيت اعتماديات أو أسرار أو محاكي/جهاز حقيقي. هذا التقرير ليس شهادة جاهزية إنتاج.

## النتيجة العامة

تم تنفيذ حزمة إصلاحات داخل المشروع، مع اختبارات وفحوص جديدة وتوضيح ما بقي غير مثبت. الفحوص التي أمكن تشغيلها في بيئة العمل نجحت:

- الفحوص الساكنة النشطة: **58/58**. يوجد **86** فحصًا تاريخيًا فاشلًا محفوظًا ومعزولًا في `apps/mobile/scripts/legacy-verifications/`؛ لا تُحسب هذه الفحوص نجاحًا، ولم تُحذف نتائجها أو سكربتاتها.
- اختبارات Node المستقلة لطوابير التخزين: **30/30**.
- فاحص قواعد الموبايل التكميلي: نجح على **208** ملف مصدر TypeScript.
- فحص بناء صياغة TypeScript/TSX فقط: **206 ملفات، 0 أخطاء صياغة**. هذا ليس بديلًا عن فحص الأنواع الكامل.
- حقول الوصول: **34/34** عنصر `TextInput` في `app/` و`src/` لها `accessibilityLabel` بحسب فحص المصدر.
- ملفات JSON الخاضعة للفحص وملفات YAML الخاصة بمسارات CI الخمسة سليمة بنيويًا؛ كما تطابق متطلبات dependencies في `apps/mobile/package.json` الـ importer المقابل في `pnpm-lock.yaml`.

**التحقق الكامل من الأنواع وVitest وESLint وبناء Android لم يكتمل محليًا**؛ لا توجد اعتماديات المشروع مثبتة في البيئة، ومحاولة الوصول إلى npm تعثرت بخطأ DNS (`EAI_AGAIN registry.npmjs.org`). لذلك لا ندّعي نجاح هذه الفحوص. أُدرجت خطواتها في CI لتشغيلها في بيئة تملك الوصول للاعتماديات.

## المرحلة 1 — الجاهزية الحرجة للإنتاج

| البند | الحالة | التنفيذ والأدلة |
|---|---|---|
| 1.1 Production signing | بوابة آمنة أُعدت؛ النشر الفعلي غير مثبت | `.github/workflows/release-mobile-production.yml` يتطلب تشغيلًا يدويًا مع تأكيد صريح وبيئة `production` وأسرار keystore، ثم يشغّل `verifyProductionSigning` قبل إنشاء AAB ويتحقق من التوقيع. لا يوجد keystore إنتاجي أو سر في المستودع، ولم يُنتج AAB هنا. |
| 1.2 Crash reporting / Sentry | غير مكتمل عمدًا | جرى تجنب الاعتماد على استيراد/`require` ساكن لحزمة غير مثبتة قد تكسر Metro. التسجيل المتاح محلي فقط. `@sentry/react-native` ومحول إرسال الأحداث واختبار وصول crash من جهاز ما زالت مطلوبة؛ وجود DSN وحده لا يثبت الإرسال. راجع `docs/mobile/checklists/SENTRY-SETUP.md`. |
| 1.3 Session على جهاز حقيقي | يتطلب اختبار جهاز | بقي اختبار login → refresh cookie → إعادة تشغيل التطبيق → logout كقائمة تحقق؛ لا يمكن إثبات دوران cookies أو التخزين الآمن من فحص ساكن وحده. |
| 1.4 SQLCipher migration | تحسين حماية الترحيل + اختبارات أُضيفت | أضيف `src/storage/sqlite-migration-integrity.ts` لمقارنة وجود الجداول وعدد الصفوف ومحتوى الصفوف قبل حذف قاعدة plaintext، ويُستخدم قبل حذف القاعدة في الترحيل والاستعادة بعد انقطاع. أضيفت اختبارات في `src/storage/__tests__/sqlite-migration-integrity.test.ts`؛ لم تُشغّل Vitest في هذه البيئة، ويلزم التحقق النهائي على قاعدة قديمة حقيقية على Android. |
| 1.5 Logout + pending outbox | إصلاح موضعي مؤكد؛ سيناريو الجهاز لم يُعتمد بعد | أزيل تعريف مكرر لـ `countPendingChat` كان يخفي أخطاء قاعدة البيانات بإرجاع صفر. أصبحت قراءة الطوابير تفشل بوضوح بدل اعتبار الخطأ طابورًا فارغًا، ويظل تسجيل الخروج مغلقًا عند فشل عدّ العمليات الخاصة. أضيفت تغطية Node لبعض منطق الطوابير؛ حالات الجهاز كاملة ما زالت تحتاج تنفيذًا. |

## شروط الإغلاق المتبقية قبل النشر

1. على بيئة ذات اتصال واعتماديات مثبتة: `pnpm install --frozen-lockfile`، ثم `pnpm --filter @marketplat/mobile type-check lint test test:storage test:sqlite` وإصلاح كل خطأ حقيقي يظهر.
2. إعداد Sentry SDK ومحول التقاط الأخطاء الأصلي والـ DSN كسر، ثم إثبات وصول JS crash وnative crash من جهاز تجريبي.
3. تشغيل workflow التوقيع ببيئة production محمية وkeystore محفوظ خارج المستودع؛ لا تعتمد AAB قبل التحقق من هوية المفتاح والتوقيع.
4. اختبار جلسة login/refresh/restart/logout وترحيل قاعدة قديمة وoutbox مع انقطاع/فشل على Android فعلي، ثم تكرار ما يلزم على iOS إن كان ضمن الإطلاق.
5. تشغيل Maestro على staging بحساب تجريبي ومراجعة إخراج Knip؛ لا تستخدم بيانات إنتاج لهذا الغرض.
6. تحديد ما إذا كان Push وAnalytics والوضع الداكن مطلوبًا في نطاق الإطلاق، وقياس الأداء على جهاز متوسط.
7. مراجعة الفحوص التاريخية الـ86 وإعادة تفعيل الفحوص المصححة تدريجيًا بدل تركها معزولة دائمًا.

**الخلاصة:** هذه النسخة تحتوي إصلاحات قابلة للإثبات وتحسينات بنيوية وفحوصًا إضافية؛ لكنها ليست بعدُ إثباتًا بأن كل البنود جاهزة للإنتاج. البنود المعتمدة على أدوات/أسرار/أجهزة أو اعتماديات غير متاحة وُسِمت صراحةً بأنها غير مختبرة أو غير مكتملة.

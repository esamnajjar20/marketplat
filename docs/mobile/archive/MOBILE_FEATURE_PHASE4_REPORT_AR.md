# تقرير Phase 4 — إدارة الصور والمفضلة

## ما تم تنفيذه

1. **إدارة صور الإعلان الحالي:** شاشة تعديل الإعلان تعرض الصور المنشورة، وتسمح بإزالة الصور أو تغيير ترتيبها محليًا قبل الحفظ.
2. **حماية قاعدة الصور:** رفع الصور الجديدة يتم عبر تدفق التعديل الحالي أولًا، ثم إزالة الصور التي اختارها المستخدم، ثم حفظ الترتيب النهائي. يظل قرار السماح بعدد الصور النهائي بيد الـ Backend، الذي يمنع حذف آخر صورة.
3. **عقود API للصور:** أضيفت دالتان إلى `manage-ads.api.ts` لاستعمال `DELETE /api/v1/ads/:id/images` و`PUT /api/v1/ads/:id/images/reorder` مع تمرير رمز CSRF عند توفره.
4. **المفضلة كصفحة مستقلة:** أضيفت `app/favorites.tsx` وتحمّل السجلات عبر صفحات من `GET /api/v1/favorites`، وتعرض الصورة والسعر والمدينة وتفتح تفاصيل الإعلان.
5. **إزالة من المفضلة:** إزالة فورية عند الاتصال باستخدام desired-state endpoint، أو وضع العملية في طابور SQLite عند عدم الاتصال، ثم تحديث ذاكرة المفضلة المحلية.
6. **التنقل:** أضيف مدخل «المفضلة» إلى رأس الصفحة الرئيسية للمستخدم المسجل.
7. **التحقق:** أضيف `verify-feature-phase4.mjs` إلى سلسلة `npm test`.

## حدود مقصودة

- إدارة حذف/ترتيب الصور المنشورة تتطلب اتصالًا بالإنترنت؛ عند انقطاعه تمنع الشاشة حفظ تغييرات الصور بدل الإيحاء بأنها أُرسلت. تعديل الحقول وإضافة الصور ما زالا يستخدمان تدفق الطابور الحالي.
- الاختبار المضاف فحص ثابت للعقود والربط؛ لا يثبت نجاح رفع الصور إلى خادم فعلي أو بناء APK.
- لا توجد تغييرات Backend في هذه المرحلة؛ المسارات المستخدمة موجودة أصلًا في `apps/api`.

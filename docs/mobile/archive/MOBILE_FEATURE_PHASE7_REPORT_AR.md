# تقرير Phase 7 — عزل العمليات دون اتصال حسب الحساب

## المشكلة التي عالجتها المرحلة

كانت قائمة العمليات المؤجلة (إنشاء/تعديل/حذف الإعلانات) تُخزّن في SQLite من دون معرّف للحساب المالك، وكان عامل المزامنة يقرأ أقدم عملية من القائمة العامة. بعد تسجيل الخروج ثم الدخول بحساب آخر، كان من الممكن محاولة إرسال عملية الحساب السابق باستخدام رمز الحساب الحالي.

## التغييرات

- إضافة `owner_id` إلى جدول `mutation_outbox` مع ترحيل متوافق لا يحذف البيانات القديمة.
- إلزام كل عملية جديدة بمعرّف المستخدم عند حفظها دون اتصال.
- جعل فحص سعة الطابور، وعرض العمليات، واختيار رأس FIFO، وحجز العملية، وإعادة المحاولة، والإلغاء ضمن حساب واحد.
- تمرير معرّف الحساب الحالي من `AuthContext` إلى عامل المزامنة عبر دورة حياة التطبيق.
- عرض عمليات الحساب الحالي فقط في شاشة `offline-queue`.
- إبقاء العمليات القديمة التي لا يمكن إثبات مالكها محفوظة، مع منع مزامنتها تلقائيًا، وإظهار تنبيه بعددها. هذا خيار fail-closed لتجنب تنفيذ تعديل أو حذف تحت حساب خاطئ.
- إضافة اختبار تحقق ثابت `verify-feature-phase7.mjs` إلى `npm test`.

## التحقق والحدود

اختبارات التحقق هذه ثابتة وتراجع عقود الكود، وليست اختبارًا لخادم فعلي أو لقاعدة SQLite على جهاز حقيقي. يجب تشغيل `npm test` و`npm run type-check` ثم اختبار تبديل الحسابين A وB مع وجود عمليات مؤجلة قبل إصدار APK إنتاجي.

العمليات القديمة غير المرتبطة بحساب لا تُنسب تلقائيًا إلى أي حساب. لا تحذف بيانات التطبيق إذا كنت تحتاج إلى تلك العمليات؛ راجع التنبيه في شاشة العمليات دون اتصال أولًا.

# المرحلة الأولى: تحسين الرسائل للشبكات الضعيفة وتقليل استعلامات قاعدة البيانات

## ما تم تغييره

1. **تفعيل نمط Cursor على طلبات الرسائل في الموبايل** عبر `cursor=true`، لأن الشاشة تستخدم `nextCursor` ولا تحتاج `total/totalPages`.
2. **إيقاف `COUNT(*)` الكامل للمحادثة** عند استخدام نمط cursor أو تحميل الرسائل الأقدم. تبقى الاستجابة التقليدية التي تعتمد على ترقيم الصفحات قادرة على إرجاع العدد.
3. **عدم تنفيذ تحديث إيصالات القراءة وإشعارات المحادثة عند تحميل صفحات التاريخ الأقدم**؛ هذه الصفحات لا تعني أن المستخدم فتح المحادثة من جديد، وتكرار التحديثات يضيف حملًا بلا فائدة.
4. **تقليل رحلة Prisma في تفاصيل المحادثة** عبر طلب إعدادات المستخدم مع المحادثة في عملية Prisma واحدة بدل استدعاء منفصل لإعدادات المستخدم.
5. **إضافة مخزن SQLite خاص بالرسائل التي زارها المستخدم**، مع نطاق حساب ومحادثة، وحد أقصى 300 رسالة لكل محادثة و2000 رسالة لكل حساب.
6. **عرض الرسائل المخزنة محليًا قبل انتظار الشبكة**، ثم دمج أحدث صفحة من الخادم وتحديث المخزن المحلي.
7. **تنفيذ جلب تعويض عند عودة الاتصال** بدل إضافة polling سريع ومتكرر.
8. إضافة تدقيق ساكن `verify-chat-pagination-audit.mjs` وربطه بالمسار الموجود أصلًا في `npm test`، وإضافة اختبارات وحدة للخادم لتوثيق سلوك cursor وتجاوز عمليات القراءة عند تصفح التاريخ.

## التحقق المنفذ

- اجتازت ملفات TypeScript المتغيرة فحص التحويل النحوي بواسطة TypeScript `transpileModule`.
- نجح تدقيق الرسائل الجديد، وتدقيق الطابور الدائم، وإعادة المحاولة idempotent، وإلغاء الطلبات عند تغيّر الجلسة.
- فشل تشغيل سلسلة `npm test` الكاملة قبل الوصول إلى اختبارات المحادثات بسبب ملف تقرير مفقود في النسخة الأصلية: `MONOREPO_PHASE23_REPORT_AR.md`، والذي تطلبه `verify-phase23.mjs`.
- لم يُشغّل TypeScript type-check أو Jest فعليًا؛ اعتماديات `node_modules` غير موجودة في النسخة المفحوصة. لم يتم تنفيذ اختبار حي على قاعدة البيانات أو جهاز Expo.

## حدود المرحلة

- لا تزال الرسائل الواردة على الموبايل بحاجة إلى ربط موثوق بقناة أحداث لحظية؛ هذه المرحلة تضيف جلبًا تعويضيًا عند عودة الشبكة ولا تدّعي أنها أضافت SSE أو Socket.IO للموبايل.
- الكاش المحلي خاص بالحساب والمحادثة ومحدود الحجم، لكنه ليس مصدر الحقيقة ولا بديلًا عن التحقق من الخادم.
- لا توجد أرقام توفير أداء مؤكدة بعد؛ يجب قياس استعلامات Prisma ووقت الاستجابة على قاعدة بيانات اختبارية قبل تقدير نسبة التحسن.

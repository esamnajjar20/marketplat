# تقرير المرحلة السادسة — تجربة أفضل مع الاتصال الضعيف

## ما تم تغييره
- تفحص الصفحة الرئيسية حالة الاتصال الحالية قبل طلب أحدث الإعلانات.
- عندما يبلّغ النظام بوضوح أن الجهاز غير متصل، لا يُرسل طلب GET معروف أنه سيفشل.
- إذا وُجدت نسخة محفوظة، تبقى معروضة دون استبدالها برسالة خطأ الشبكة.
- إذا لم توجد نسخة محفوظة، تظهر رسالة عربية توضّح أن النتائج غير متاحة دون اتصال وكيفية إعادة المحاولة.
- تُصفّر مؤشرات التحميل والتحديث عبر مسار `finally` حتى لا تبقى الواجهة عالقة.
- أُضيف فحص ثابت للمرحلة السادسة إلى سكربت `npm test`.

## الملفات
- `app/index.tsx`
- `package.json`
- `scripts/verify-homepage-ux-phase6.mjs` (جديد)
- `HOME-PAGE-UX-PHASE6-REPORT-AR.md` (جديد)

## التحقق والحدود
تم تشغيل فحوص الصفحة الرئيسية للمراحل 3–6، إضافة إلى فحص صياغة `package.json` وسلامة ZIP. هذه فحوص ثابتة وليست اختبارًا فعليًا على جهاز. لم يتم تأكيد بناء Expo أو فحص TypeScript الكامل. يعتمد تخطي الطلب على إبلاغ NetInfo عن انقطاع مؤكد (`isConnected === false`)؛ أما الحالات غير المعروفة فتستمر إلى مسار الشبكة المعتاد.

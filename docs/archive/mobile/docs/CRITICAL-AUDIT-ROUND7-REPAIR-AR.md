# تقرير تتبّع وإصلاح النقد الشامل — MarketPlat Mobile (الجولة السابعة)

**قاعدة العمل:** `marketplat-mobile-round6-uiux-repaired.zip`  
**النطاق:** `apps/mobile`، إعدادات Android وCI المرتبطة، وعقد `/health` في API.  
**تاريخ التنفيذ:** 31 أكتوبر 2026.

## 1. الإصلاحات المنفذة

### H1 — توقيع إصدار Android
- أزيل الرجوع الصامت من توقيع `release` إلى `signingConfigs.debug`.
- إعداد `release` يستخدم بيانات التوقيع الإنتاجي فقط. عند غياب أي من المتغيرات الأربعة أو ملف keystore يفشل حاجز `verifyProductionSigning`.
- رُبط حاجز التوقيع بمهام بناء Release، وبقي `assembleDebug` للبناء التجريبي.
- عُدّلت سيرتا Android الاختباريتان لإنتاج APK/AAB من `debug` فقط، ولم يعد مسار الاختبار يحاول إنتاج Release بلا أسرار إنتاجية.
- تمت مزامنة `apps/mobile/package.json` مع `app.json` على الإصدار `0.1.1`.

### H4 — كشف الاتصال
- أصبح NetInfo يفحص `GET /health` الخفيف بدل مسار بيانات التصنيفات.
- أي استجابة HTTP بين 200 و599 من مسار `/health` تعني أن مسار الشبكة إلى الخادم قابل للوصول؛ لا تحوّل `429` أو `503` وحدها حالة الشبكة إلى «لا يوجد إنترنت».
- بقي فشل الاتصال على مستوى النقل/انتهاء المهلة حالة غير قابلة للوصول. لذلك ما زال التمييز الكامل بين انقطاع الإنترنت وتعذر الوصول إلى مضيف API بحاجة إلى قياس مستقل على الجهاز والشبكات الفعلية.

### M1 — عميل API والذاكرة المؤقتة
- خُفّضت المهلة الافتراضية من 12 إلى 10 ثوانٍ، وأصبحت إعادة GET العابرة تستخدم المهلة نفسها بدل تمديد المحاولة الثانية إلى 35 ثانية.
- يسمح عميل API بقراءة نسخة cache المسموح بها بعد أخطاء النقل وHTTP `5xx` و`429`، مع استمرار التحقق من البيانات عبر مخطط Zod.
- أصبحت نتيجة cache تحمل `__cachedAt` و`__staleForMs` إلى جانب `__fromCache`.
- يقرأ العميل `Retry-After` بصيغتي عدد الثواني أو تاريخ HTTP، ويضع `retryAfterSeconds` في `ApiError.errorMeta` ويعرض مدة الانتظار عند توفرها. لا ينام العميل تلقائيًا؛ إعادة المحاولة المجدولة تبقى مسؤولية الواجهة/المستدعي.
- فُصل إلغاء الطلب بإشارة المستدعي عن انتهاء مهلة الاتصال؛ الطلب الملغى لا يعاد ولا يستبدل بنتيجة cache.
- ضُيّقت ترجمة رسائل `phone/password` حتى لا يُترجم كل نص يحتوي الكلمة إلى خطأ إدخال. أضيفت صياغة خاصة لقفل الحساب بسبب كثرة محاولات الدخول.

### M2 — استعادة الجلسة عند العودة
- أضيف مستمع `AppState`؛ عند عودة التطبيق إلى المقدمة يجدد الجلسة إذا انتهى رمز الوصول أو اقترب انتهاؤه، مع حماية من تبديل المستخدم أثناء الطلب ومن بدء التجديد أثناء عملية مصادقة/خروج قائمة.
- لم يُحسم بقاء كوكي `httpOnly` بعد إغلاق التطبيق بالكامل؛ هذا يحتاج اختبارًا فعليًا على Android وقراءة `Set-Cookie` من بيئة الخادم.

### M3 — الخروج والبيانات المحلية
- أصبح الخيار الافتراضي «خروج مع الاحتفاظ بالبيانات المشفرة لهذا الحساب».
- أضيف خيار منفصل ومدمّر «خروج وحذف البيانات»، ولا ينفذ إلا بعد موافقة صريحة ومع وجود معرّف مالك محدد.
- لا يُستنتج أن قاعدة البيانات فارغة عندما يتعذر فحص طابور العمليات.

### M4 — صور المحادثة
- تمر صورة الرسالة الآن عبر `isAllowedMediaUrl` نفسها المستخدمة للصوت والملفات، وتُرفض الروابط غير المسموحة قبل تمريرها إلى مكوّن `Image`.

### H5 — حالة البيانات في الشاشات
- في شاشة «إعلاناتي»، أصبح تحديث الصفحة الأولى بعد العودة من شاشة التفاصيل يحافظ على الصفحات التي حمّلها المستخدم، ويزيل التكرار، ويقص النتائج التي تجاوزت عدد الصفحات الجديد من الخادم.
- أضيف دعم `AbortSignal` لطلبات صفحات إعلاناتي، وتُلغى طلبات الصفحة/تحميل المزيد عند مغادرة الشاشة.
- أزيل `QueryProvider` و`useHomeAdsQuery` غير المستخدمين اللذين كانا يوحيان بوجود TanStack Query دون تثبيت المكتبة أو ربط المزوّد.
- حُدث `docs/ARCHITECTURE.md` ليصف الواقع: حالة التحميل/الخطأ/الترقيم ما زالت مملوكة لكل شاشة، ولا توجد طبقة server-state موحدة حتى الآن.

### L4/L5 — اتساق وتنظيم
- تساوى إصدار حزمة الموبايل مع إصدار Expo: `0.1.1`.
- نُقلت 70 وثيقة Markdown من جذر `apps/mobile` إلى `apps/mobile/docs/history/` دون تغيير محتواها؛ أضيف فهرس للأرشيف.
- حُذف ملف TypeScript قديم لطابور المسودات بعد التأكد من عدم وجود مستوردين له، مع بقاء تنفيذ MJS المعتمد.
- عُدلت فحوص توقيع الإصدار واسترجاع lease لتقبل اختلاف المسافات في SQL، بدل فشلها بسبب صياغة نصية ضيقة.

## 2. ما لم يُغلق بعد

| البند | الحالة بعد الجولة |
|---|---|
| H2 — إرسال الأعطال إلى Sentry/خدمة إنتاجية | مفتوح. لا يوجد SDK أو adapter إنتاجي مثبت. لم أضف اعتمادًا غير متوفر ولم أدّع تفعيل DSN. |
| H3 — اختبارات سلوكية وواجهة وE2E | جزئي. أضيفت اختبارات API/pagination/NetInfo، لكن لم تُشغّل بسبب غياب Vitest والاعتماديات، ولم تُضف بعد تغطية العرض وMaestro المطلوبة. |
| H4 — الفصل التام بين الإنترنت ومضيف API | جزئي. عولج شرط `200`، لكن فشل الاتصال بمضيف API دون أي استجابة HTTP لا يثبت وحده انقطاع الإنترنت العام. |
| H5 — طبقة تحميل موحدة على مستوى الشاشات | جزئي. أصلحت مشكلة إعلاناتي وأزلت أغلفة TanStack الميتة؛ لم تُنقل الرئيسية والمحادثات والإعلانات والتفاصيل كلها إلى عقد تحميل موحد. |
| H6 — RTL أصلي | مفتوح بقرار واعٍ. لم أغيّر `forceRTL(false)` أو `supportsRtl=false` دون اختبار جهاز عربي وخطة تحويل للمكونات. |
| M2 — عمر كوكي التجديد بعد الإغلاق | غير محسوم دون اختبار الجهاز ورؤوس `Set-Cookie` الفعلية. |
| M5 — حارس وصول مركزي للمسارات الخاصة | مفتوح؛ يتطلب مصفوفة تصنيف للمسارات العامة والخاصة قبل النقل إلى route groups/guards. |
| M6 — Android App Links وiOS Universal Links | مفتوح؛ يتطلب نطاقًا مملوكًا وملفات `assetlinks.json` و`apple-app-site-association` وإعداد الخادم/المتجر. |
| M7 — سياسة موحدة لتعارضات طوابير offline | غير محسوم؛ لم أدمج الطوابير أو أغيّر سلوك عمليات متعارضة دون عقود الخادم واختبارات إعادة تشغيل. |
| L1 — تنسيق جميع الملفات والأسطر الطويلة | مفتوح جزئيًا؛ لم أطبّق Prettier شاملًا على 66 ملفًا دون تشغيل الاختبارات ومراجعة diff. |
| L2 — أداء جميع القوائم | مفتوح؛ لا توجد قياسات جهاز/FPS أو حصر runtime لطول القوائم في هذه البيئة. |
| L3 — سياسة TTL/LRU للذاكرة | جزئي؛ أصبحت أزمنة cache قابلة للقراءة، لكن لم أغيّر سياسة الإخلاء أو أفرض حدًا زمنيًا موحدًا للأسعار والتوفر. |
| L4 — إعدادات Updates، معرفات العمليات، الأيقونات/الوضع الداكن | جزئي؛ تمت مزامنة الإصدار فقط. بقيت metadata Updates والإعدادات/الأيقونات/المعرّفات بحاجة إلى قرار وتحقق مستقل. |
| L5 — ملفات patch ومخرجات التدقيق بجذر المستودع | جزئي؛ نُظّم جذر `apps/mobile`، لكن لم أنقل ملفات patch و`test-results` من جذر المستودع لأنها خارج نطاق التطبيق وقد تكون مطلوبة في سير العمل. |

## 4. حدود التحقق

لم تتوفر `node_modules` ولا أداة `pnpm` في بيئة التنفيذ. محاولة تشغيل Corepack/تنزيل pnpm لم تنجح بسبب خطأ شبكة `EAI_AGAIN`. لذلك لم يُنفذ `type-check` أو ESLint أو Vitest أو `expo-doctor` أو Gradle أو بناء APK/AAB أو فحص التوقيع الفعلي أو اختبار محاكي/جهاز. كما أن مشغل التحقق الشامل تجاوز مهلة التنفيذ المتاحة ولم يكتمل.

أُغلقت عيوب ملموسة في توقيع Release، واكتشاف أخطاء الخادم، وتحقق روابط الصور، واحتفاظ الخروج بالبيانات، وسلوك عميل API، وجزء من تحديث القوائم. لكن الجولة **لا تجعل التطبيق جاهزًا للنشر**: ما زالت مراقبة الأعطال، تغطية السلوك/الواجهة، تعميم حالة البيانات، حسم RTL، واختبارات الكوكي والبناء الفعلي متطلبات مفتوحة.

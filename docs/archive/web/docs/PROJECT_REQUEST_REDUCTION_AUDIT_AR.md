# تدقيق تقليل طلبات API على مستوى MarketPlat

## خلاصة التدقيق

تمت مراجعة واجهات الصفحات، مكوّنات الـ hubs، React Query hooks، واستدعاءات API المرتبطة بالداشبورد والمتجر والمبيعات والخدمات والإعدادات والملف الشخصي والمحادثات. التركيز كان على الطلبات التي تُحمّل بيانات تبويب غير ظاهر أو بيانات يمكن مشاركتها من query key موجود.

## تعديلات جديدة في هذه الحزمة

1. **الداشبورد — النشاط والإشعارات:** أصبح قسم «التحديثات والنشاط» قابلاً للفتح. لا يُركّب `RecentActivityFeed` و`SellerTodayTasks` ولا يبدأ طلب `/activity/dashboard` إلا بعد فتحه. قائمة الإشعارات الأخيرة لا تُطلب إلا بعد الفتح.
2. **المبيعات — إعدادات التكلفة:** كان `SalesTabsHub` يطلب إعدادات التكلفة حتى عند فتح تبويبات العملاء والديون والأقساط والتقارير والتحليلات والذكاء. أصبح الطلب مفعّلاً فقط في `overview` و`sales` و`costs`؛ وتظل مكوّنات التبويبات التي تحتاجه تشارك query key نفسه.
3. **لوحة المتجر — بيانات المتجر:** كان `MyStoreTabsHub` يستدعي `useMyStore()` على جميع التبويبات للحصول على تسميات المنتجات. أصبح الاستعلام مفعّلاً فقط في `products` و`analytics`. تبويب `overview` يحمل بياناته من `MyStoreHub` نفسه، أما بقية التبويبات فلا تحتاج الطلب.
4. **تجميع التبويبات:** أضيف `onActiveChange` اختياري إلى `TabsHub` حتى تتمكن الصفحات التي تعتمد على التبويب النشط من تفعيل/تعطيل استعلاماتها دون كسر hubs الأخرى.

## تغييرات سابقة من المحادثة أُعيد دمجها

- الداشبورد: استخدام `totalAds` من `/ads/me/stats` بدلاً من طلب `/ads/me?limit=1` المنفصل.
- البحث: debounce اقتراحات البحث 500ms وتطبيع نص البحث قبل بناء query key والطلب.
- إعدادات الحضور: منع تداخل heartbeat وتجميع عمليات Redis ذات الصلة في pipeline.
- خدماتي: الاحتفاظ ببيانات التحليلات السابقة أثناء تبديل الفترة، ومشاركة استعلام لوحة مقدم الخدمة بين الملخص والقائمة، وإضافة فهرس مناسب لقائمة الخدمات.
- طلبات الخدمة: فهارس customer/status/date مع migration.
- لوحة التحديثات: فتح النشاط وقائمة الإشعارات عند الطلب مع إبقاء عدّاد الجرس العام.

## أنماط موجودة مسبقاً تم التحقق منها ولم نكرر تعديلها

- تبويبات الإعدادات والخدمات والمتجر والمبيعات تستخدم تحميل مكونات التبويب النشط فقط عبر `TabsHub` و`next/dynamic`؛ لذلك لا تُحمّل كل قوائم التبويبات عند فتح الصفحة.
- قائمة الإشعارات في `NotificationBell` مفعّلة فقط عند فتح القائمة، بينما عدّاد غير المقروء يبقى عاماً حتى يعمل الجرس عبر الصفحات.
- الملف الشخصي العام يجمع حالة المتابعة والحضور في `useProfileInteractionState`، ويعطّلها في الملف الشخصي الذاتي؛ والقصص لا تُحمّل إلا عند الضغط على الصورة.
- تفاصيل المحادثة تتضمن حالة الحظر والحضور في استجابة المحادثة، وقائمة المحادثات تجلب حالات الحظر على دفعة واحدة.
- عدة مراحل من تجميع API (العملاء/الأقساط وغيرها) موجودة في المصدر، واجتازت تدقيقاتها المحددة.

## طلبات أبقيناها عمداً

- `/notifications/unread-count`: يبقى للجرس العام. لوحة الداشبورد تشارك نفس query key ولا يفترض أن تنشئ طلباً مستقلاً.
- بيانات الملخص التي تظهر مباشرة في التبويب النشط: لا نؤخرها لأن ذلك سيؤخر المحتوى الذي فتح المستخدم الصفحة من أجله.
- قوائم البيانات عند الانتقال إلى تبويبها: تحميلها عند فتح التبويب هو السلوك المقصود، وليس طلباً زائداً.

## ملفات التعديلات التاريخية غير المتاحة

تم دمج كل حزم التعديلات السابقة التي كانت ملفات ZIP الخاصة بها متاحة في مساحة العمل الحالية. توجد مراحل ذُكرت سابقاً في المحادثة (مثل بعض تعديلات الصفحة الرئيسية والمتجر والمبيعات/البيانات الأولى) لكن ZIP الأصلي لها لم يكن متاحاً هنا، ولم أعد إنشاء محتواها بالتخمين. لذلك هذه الحزمة تضم كل ما أمكن استعادته والتحقق منه، وليست ادعاءً بأن كل ملف ذُكر تاريخياً أصبح موجوداً.

## طريقة الدمج

فك ضغط الملفات من جذر مستودع `marketplat` مع الحفاظ على المسارات. راجع ملفات Prisma migrations ثم نفّذ `npx prisma migrate deploy` من مجلد API عند اعتماد التغييرات، وبعدها شغّل `npm run type-check` والاختبارات والبناء في بيئة المشروع.

# تحسين طلبات لوحة المتجر

## ما أثبته سجل الشبكة

- أربعة طلبات `GET /products/me` كانت مرتبطة بأشكال استخدام مختلفة: قائمة المنتجات (10)، تسمية المنتجات في العروض (100)، اختيار منتج نشط داخل نموذج العرض (100)، وقائمة المخزون (20).
- ليست هذه الطلبات الأربعة نسخًا متطابقة: لكل منها غرض وفلاتر/ترقيم مختلف، ولذلك لم يتم دمجها قسرًا في استعلام واحد قد يفسد الترقيم أو نتائج المخزون.
- طلب قائمة المنتجات النشطة في `PromotionForm` كان يحدث حتى عندما يكون مربع إنشاء العرض مغلقًا، لأن المكوّن يبقى مركبًا داخل تبويب العروض. هذا طلب غير ضروري عند فتح التبويب.

## التعديلات

1. أصبح تحميل منتجات اختيار العرض مشروطًا بفتح `PromotionForm` فقط. عند إغلاق النموذج لا يرسل طلب `products/me?status=ACTIVE&limit=100`.
2. أصبح تحميل قائمة المنتجات المستخدمة فقط لعرض أسماء المنتجات في بطاقات العروض مشروطًا بوجود عروض فعلية. المتجر الذي لا يملك عروضًا لا يحتاج إلى جلب كتالوج المنتجات لهذا الغرض.
3. لم تتغير استعلامات قائمة المنتجات أو المخزون، ولا ترقيم الصفحات أو فلاتر الحالة والتوفر.
4. أبقينا سياسة `CACHE_TTL.myAds` البالغة 120 ثانية كما هي؛ لا يوجد مبرر لرفعها أو خفضها استنادًا إلى سجل واحد.

## الطلبات الأخرى

طلبات التحليلات، أعضاء المتجر، دعوات الفريق، ملخص المخزون، سجل حركات المخزون، أنواع المتاجر وحقول النوع تخص أقسامًا مختلفة. مكوّن `TabsHub` يعرض محتوى التبويب النشط فقط، ولذلك لا يصح اعتبار كل طلب منها تكرارًا لمجرد ظهوره خلال جلسة التصفح. لم نحذفها أو نؤخرها عشوائيًا.

## ما لم يثبته السجل

طلب `GET /products/me?page=1&limit=10` استغرق 3297ms. لا يحدد سجل المتصفح وحده إن كان السبب استعلام قاعدة البيانات أو بدء تشغيل خدمة Render أو انتظار Redis أو الشبكة. يلزم ربطه بسجلات API/Prisma مع request ID وقياس زمن كل مرحلة قبل تغيير الباك إند.

## التحقق

شغّل `node scripts/store-dashboard-requests-audit.mjs` من مجلد `frontend`. لم يتم ادعاء تشغيل Vitest أو `tsc --noEmit` أو بناء Next.js ضمن هذه الحزمة.

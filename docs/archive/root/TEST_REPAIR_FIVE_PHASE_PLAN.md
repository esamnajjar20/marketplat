# Marketplat — خطة إصلاح الاختبارات المتبقية في خمس مراحل

الأرقام المرجعية مأخوذة من سجل CI الأصلي: 122 ملف اختبار Frontend وملف Backend واحد، مع 475 فشلًا في Frontend و6 في Backend. لا تعتبر أي مجموعة منتهية حتى يعاد تشغيل الاختبارات الفعلية.

## المرحلة 1 — إصلاح عقود React Query واختبارات الخطافات (بدأت)
- إصلاح غياب QueryClient في اختبارات `usePendingMessages` وصفحة المتجر.
- مطابقة اختبار `useAdjustProductStock` مع الوسيط الاختياري الثالث.
- تحديث اختبارات `ProductsGrid` لتختبر `useInfiniteQuery` و`productsApi.getAll` المستخدمين فعليًا بدل hook قديم أزيل من التنفيذ.
- تحديث `useNearbyProvidersForHome` ليتحقق من مصدر بيانات الصفحة الرئيسية الحالي، بدل عقد GPS قديم لم يعد مستخدمًا.

## المرحلة 2 — API wrappers وعميل HTTP (نحو 15–20 ملفًا)
- تثبيت عقود method/path/body/query/config headers.
- التحقق من ترويسات idempotency وmultipart وAbortSignal وtoken/error interceptors.
- عدم حذف وسيط مقصود من التنفيذ فقط لمجاراة assertion قديم.

## المرحلة 3 — التنقل وPWA وواجهات البحث/الصفحات العامة (قيد التنفيذ)
- عُدّلت اختبارات ProtectedMobileNav لتنتظر تركيب بوابة DOM (portal) بعد commit بدل البحث المتزامن قبل ظهورها.
- عُدّل اختبار PwaBootstrap لانتظار اكتمال getAppMode غير المتزامن قبل تأكيد تسجيل Service Worker.
- عُدّلت اختبارات InstallPrompt لتنتظر bootstrap غير المتزامن لقدرات التثبيت، وأزيل mock مكرر واختبار قديم يعتمد على isNativePlatform بعد انتقال القرار إلى supportsInstallPrompt.
- المتبقي في هذه المرحلة: MobileNav وSearchResultsMapInner وبقية ملفات البحث والصفحات العامة.
- حالات loading/empty/error وARIA وروابط المسارات وخرائط البحث.
- إصلاح mocks الخاصة بالمتصفح/IntersectionObserver/Map APIs حيث تكون غير مكتملة.

## المرحلة 4 — النماذج وعمليات mutation ولوحات الإدارة (بدأت)
- راجعت عقد حفظ الإعلان عند فشل رفع/حذف الصور: خطأ الشبكة يعالج مسار المسودة دون اتصال، بينما الخطأ غير الشبكي يوقف PATCH. حدّثت اختبار AdForm ليطابق السلوك المقصود في T792.
- حدّثت اختبارات إلغاء AdForm لتضبط سجل المتصفح كجلسة داخل التطبيق، حتى تختبر history.back بدل فرع الرجوع الاحتياطي إلى قائمة الإعلانات.
- حدّثت AdminAdsTable tests لاستخدام router.replace، وهو ما يستعمله المكوّن الفعلي لتغيير البحث والفلترة مع حذف page.
- جعلت اختيار زر إيقاف المنتج في AdminProductsTable محددًا بالـ aria-label الخاص بالصف، لتجنب الالتباس مع أزرار مكررة في تخطيط العرض المزدوج.
- ما زالت نماذج الخدمات والملف الشخصي وبقية جداول الإدارة بحاجة إلى مراجعة واختبار فعلي.

## المرحلة 5 — البطاقات والقوائم وBackend (بدأت، غير مكتملة)
- حدّثت `RecentAds.test.tsx` من hook قديم (`useAdsForHome`) إلى مصدر البيانات الحالي `useHomeFeed`، مع حالات loading/data/data-saver/error.
- حدّثت `RelatedServices.test.tsx` إلى `useServiceRecommendations` الحالي، واختبرت التفعيل بواسطة `categoryId` أو `serviceTypeId` واستبعاد العنصر الحالي.
- حدّثت `ForYouMixedSection.test.tsx` لتختبر العقد الحالي: `useHomeFeed` و`useForYouItems` وحالات التحميل والخطأ والضيف/المستخدم.
- أزلت fake timers من اختبار إعادة محاولة push الذي كان يعلّق عند تسجيل المؤقت بعد تقدّم الساعة؛ الاختبار يستخدم الآن مهلة retry الفعلية 1.5 ثانية.
- بقيت مئات الاختبارات في قائمة CI بحاجة إلى مراجعة؛ لم تُشغّل هذه التعديلات فعليًا بعد بسبب تعطل/نقص بيئة الاعتماديات. لا تُعد المرحلة أو المشروع منتهيًا حتى تنجح الاختبارات الفعلية.

## معيار الإنجاز
لا يوضع أي ملف على أنه ناجح إلا بعد تشغيل الاختبار نفسه بنجاح. التدقيقات الساكنة مفيدة لكنها لا تحل محل Vitest/Jest/type-check.

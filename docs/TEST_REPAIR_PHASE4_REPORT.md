# تقرير المرحلة الرابعة — النماذج ولوحات الإدارة

## التغييرات
- `frontend/__tests__/components/AdForm.test.tsx`: جعل اختبار فشل الصور يطابق السلوك المقصود؛ فشل الشبكة يسمح بمحاولة حفظ الحقول عبر `updateAd` لدعم حفظ المسودة دون اتصال، بينما الخطأ غير الشبكي يوقف العملية. كما ضُبط سجل التنقل في اختبارات الإلغاء حتى تختبر فرع `history.back()`.
- `frontend/__tests__/components/AdminAdsTable.test.tsx`: التوقعات تستخدم `router.replace` بدل `push` لأن المكوّن الفعلي يستعمل `replace` لتحديث معلمات البحث والحالة ومسح رقم الصفحة.
- `frontend/__tests__/components/AdminProductsTable.test.tsx`: اختيار زر إيقاف المنتج باستخدام `aria-label` المحدد للصف لتفادي مطابقة أكثر من زر في التخطيط المتجاوب.
- تحديث `docs/TEST_REPAIR_FIVE_PHASE_PLAN.md` بحالة المرحلة الرابعة.

## التحقق
- فحوصات JavaScript syntax لـ `frontend/public/sw.js` نجحت.
- فحوصات البنية النصية الأساسية للملفات الثلاثة المعدلة نجحت.
- جميع 59 سكربت تدقيق ساكن داخل `frontend/scripts/*audit*.mjs` خرجت بنجاح عند تشغيلها من مجلد `frontend`.
- لم يتم تشغيل Vitest؛ ملفه التنفيذي غير متوفر في بيئة العمل الحالية. لذلك لا تعتبر اختبارات الملفات المعدلة مؤكدة النجاح حتى تُشغّل في بيئة الاعتماديات الكاملة.

## ما تبقى
هذه دفعة من المرحلة الرابعة وليست إكمالًا لكل نماذج المشروع أو كل اختبارات الإدارة. ما زالت مراجعة بقية الملفات والمرحلة الخامسة وتشغيل الاختبارات الفعلية مطلوبة.

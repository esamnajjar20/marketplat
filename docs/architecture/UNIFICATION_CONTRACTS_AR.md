# عقد توحيد الأنظمة – MarketPlat

**الإصدار:** 1.1  
**التاريخ:** 27 نوفمبر 2026  
**الهدف:** توثيق مصدر الحقيقة المشترك، وحدود مسؤولية كل منصة، والفحوص التي تمنع عودة الاختلافات.

## 1. القاعدة المعمارية

تعريفات المجال التي تتشاركها API وWeb وMobile يجب أن تصدر من `packages/contracts`. لا تُنسخ Enums أو أنواع الحالة أو تسميات المستخدم أو قواعد التحقق إلى تطبيق آخر ما دام لها معنى مشترك.

الحزمة المشتركة هي عقد بيانات/تحقق، وليست مكتبة واجهة أو مستودعاً عاماً لكل سلوك داخلي. تبقى مكونات العرض، التخزين المحلي، Query Cache، Navigation، وأدوات المنصة داخل التطبيق الذي يملكها.

## 2. مصدر الحقيقة

| المجال | العقد المعتمد | المستهلكون |
|---|---|---|

## 3. الأدوار

`packages/contracts/src/roles.ts` هو مصدر ترتيب الأدوار وسياسة المقارنة المشتركة (`ROLE_RANK`, `isAdminTier`, `canManageRole`). يستخدم Backend القاعدة نفسها التي تستعملها Web لإخفاء/إظهار إجراءات الإدارة.

هذا العقد لا يستبدل تفويض Backend. يجب أن يستمر الخادم في فرض ملكية المورد، ومنع تعديل الدور الذاتي، والتحقق من قيود آخر مدير، والصلاحيات الخاصة بكل Route. فحص واجهة المستخدم ليس حدّاً أمنياً.

## 4. حالات المجال والتسميات

قِيَم Enums في `domain.ts` تُقارن مباشرةً مع Enums في Prisma بواسطة `packages/contracts/test/unification-parity.test.mts`. تغطي المجموعة الحالية 45/45 من Enums في Prisma، إضافة إلى عقد NotificationType المنفصل الذي يغطي 40 نوع إشعار. وتشمل العقود كذلك AuditEventType وFraudSignalType وAnalyticsEventType وSalesAutomationEventType وحقول المتاجر والخدمات والقصص والمتابعة والأنشطة والمفضلة. لا تُستخدم خريطة حالة عامة عند وجود مجال محدد؛ فـ `ACCEPTED` مثلاً قد تكون تسمية طلب مختلفة عن تسمية عرض أو طلب خدمة.

تفضّل الشاشات `DOMAIN_STATUS_LABELS.<domain>` أو `domainLabel(domain, value)` بدلاً من إنشاء قاموس محلي. اكتملت خريطة التسميات العربية لأحداث التدقيق وإشارات الاحتيال، بما في ذلك الأحداث الستة التي كانت تظهر سابقاً دون تسمية محددة. وقد رُبطت استهلاكات Web وMobile الأساسية بعقود المجال بدلاً من تكرار اتحادات نصية محلية. تظل الألوان، variants، وترتيب الأزرار محلية لكل منصة لأنها قرارات عرض لا تغيّر معنى الحالة.

لا تُضاف إلى عقد Prisma حالات واجهة ليست حالات تخزين. أمثلة انتقالات الخطوات، أو حالات العرض المحسوبة، تبقى في طبقة الواجهة مع توضيح أنها ليست Enum دائم.

## 5. عقود API وPagination

يُستخدم `ApiSuccessEnvelope<T>` و`ApiErrorEnvelope` من العقد المشترك. تُعرّف Offset pagination وCursor pagination بعقدين منفصلين حتى لا تُعامل `cursor/hasMore` على أنها `page/totalPages`.

تستطيع التطبيقات إنشاء wrappers محلية رفيعة لتوافق مكتبة HTTP أو مكتبة Query، لكن لا تعيد تعريف شكل envelope أو حقول metadata من الصفر. تستخدم عقود Mobile/API/Web مغلفات الاستجابة المشتركة، وتستند أنواع Offset وCursor إلى تعريفين منفصلين. يسمح wrapper محلي بتحويل الاستجابة إلى واجهة المكتبة المستهلكة دون أن يصبح مصدراً ثانياً للعقد. أي توسعة للـ metadata تُضاف إلى العقد أولاً ثم تُطبّق في الخادم والمستهلكين.

## 6. التنسيق

المحددات المشتركة:

- Locale: `ar-PS-u-nu-latn`.
- Time zone: `Asia/Gaza`.
- الحسابات المالية تعرض منزلتين عشريتين، مع رمز ILS `₪` عند عدم تحديد رمز آخر.
- القيمة المالية المفقودة تعرض `غير متاح`، ولا تتحول ضمنياً إلى صفر.
- سعر الإعلان/المنتج يبقى تنسيقاً منفصلاً بلا كسور افتراضياً.
- الدوال منفصلة للتاريخ والوقت والتاريخ مع الوقت، والاختيار الافتراضي في `formatDate` هو التاريخ فقط.

يجب ألا تستخدم طبقة العرض هذه لحساب أرصدة أو إجماليات مالية؛ عمليات المجال المالية تعتمد الحسابات الدقيقة في Backend/Prisma Decimal.

## 7. الإشعارات وGo Worker

`notifications.ts` هو العقد المرجعي لأنواع الإشعارات وفئاتها ومفاتيح التفضيل والقيم الافتراضية. يحتفظ Go Worker باستعلامات SQL وتنفيذ Go الخاص به؛ لا تُستبدل تلك العمليات تلقائياً باستدعاءات TypeScript. أضيف اختبار تكافؤ ساكن يتأكد من أن قيم NotificationType ومفاتيح `notificationPreferences` المستعملة في Go موجودة في العقد المشترك.

هذا الفحص يمنع استخدام مفتاح خاطئ، لكنه لا يولّد Go constants ولا يثبت سلوك التفضيل عند التشغيل. عند إدخال مفتاح جديد يجب تحديث العقد أولاً، ثم مستهلكي Go/SQL، ثم اختبار التكافؤ.

تظل BullMQ وGo Durable Push Outbox محركين مختلفين عمداً، ولكل منهما مهمة تشغيلية مختلفة. التوحيد في عقد الرسالة وسياسة التفضيلات وحالة التسليم، وليس في محرك المعالجة.

## 8. ما يبقى منفصلاً عمداً

- React Query/IndexedDB في Web وSQLite/Expo في Mobile: مخازن مختلفة وواجهات تشغيل مختلفة.
- Cache stores ومفاتيح Query الخاصة بالمنصة: لا ينبغي نسخ Query keys بين Web وMobile، بينما خوارزمية بناء المفاتيح المشتركة التي تحتاج تطابقاً حرفياً تُختبر على النسخ المعتمدة.
- ألوان الشارات، المكونات، والتنقل: تُترجم العقد إلى UI مناسب لكل منصة.
- BullMQ وGo Worker: محركات تنفيذ منفصلة وراء سياسات مشتركة.
- حزمة `frontend` مستقلة بإدارة npm و`package-lock.json`، بينما بقية الـ monorepo تعتمد pnpm؛ لا تُدمج دون خطة ترحيل للحزم وسير العمل.
- TypeScript 6.0.3 للموبايل منفصل حالياً بسبب متطلبات Expo SDK/peer dependencies؛ TypeScript 5.9.3 يستخدم في API وWeb وContracts وWorkers. تم تثبيت Zod على 3.25.76 حيث تستخدمه التطبيقات، وNode 22.18.0 مثبت في `.nvmrc` و`.node-version` وCI.
- `AdImageOfflineOperation` هو سجل idempotency/replay دائم. غياب العلاقات الخارجية فيه مقصود حتى لا يُحذف سجل منع إعادة التشغيل بحذف الإعلان أو المستخدم؛ استعماله موثق ومختبر ساكناً في عقد التوحيد.

## 9. بوابة منع الانحراف

يجب تشغيل هذه الفحوص قبل الدمج:

```bash
node --experimental-strip-types --test packages/contracts/test/unification-parity.test.mts
node --experimental-strip-types apps/mobile/scripts/verify-web-mobile-parity.mts
node --experimental-strip-types apps/mobile/scripts/verify-theme-system.mts
node --experimental-strip-types apps/mobile/scripts/verify-native-chat-parity-audit.mts
node --experimental-strip-types tools/verify-prisma-layout.mts
```

ثم في بيئة التطوير/CI الكاملة:

```bash
pnpm run type-check:all
pnpm run test:all
pnpm run build:all
```

الفحوص الثابتة ليست بديلاً عن اختبارات API الحية، وسباقات Redis/PostgreSQL، أو اختبارات الأجهزة الفعلية.

## 10. نطاق التحقق المنفذ

- اختبارات تكافؤ العقود: 20/20 ناجحة.
- Enums في Prisma: 45/45 مغطاة بعقود مشتركة.
- أنواع الإشعارات: 40 نوعاً ضمن العقد المشترك، مع اختبار انتماء الأنواع إلى الفئات.
- سكربتات التدقيق الثابتة التي أُعيد تشغيلها: 10 ناجحة.
- فحص صياغة TypeScript/TSX/MTS/CTS: 136 ملفاً من الملفات المتغيرة، دون أخطاء صياغية.
- ملفات `package.json`: 9 سليمة نحويّاً؛ وملفات YAML الخاصة بالـ workflows وملف القفل: 34 سليمة نحويّاً.

هذه أرقام فحوص ساكنة ومحددة وليست نسبة اكتمال وظيفي أو دليلاً على نجاح البناء.

## 11. حدود هذا الإصدار

هذا الإصدار يوحّد العقود والسلوكيات التي يمكن مشاركتها من دون تغيير تصميم التخزين أو محركات الخدمات. ويظل هناك تحسين معماري غير عاجل: بعض عمليات القراءة البسيطة في Controllers تستعلم Prisma مباشرة بدلاً من المرور عبر Repository؛ لم تُنقل قسراً إلى طبقة جديدة لأن ذلك سيضيف طبقات شكلية دون إثبات فائدة أو اختلاف سلوكي. كذلك يظل اختبار مفاتيح Go ساكناً ولا يولّد ثوابت Go آلياً. لا يضيف Migration إلى Prisma، ولا يغير أسماء API العامة، ولا يحذف أي محرك. لا يزال يلزم تشغيل type-check والبناء واختبارات Jest/Vitest/Go الكاملة في بيئة تحتوي Node 22.18 أو أحدث، pnpm واعتماديات المشروع، وبيئة اختبار PostgreSQL/Redis.

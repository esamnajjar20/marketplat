# نظام التحميل في الواجهة

## القواعد

- `LoadingState` هو طبقة العرض الموحدة لحالات التحميل: `page` للصفحات، `section` للأقسام، `inline` للإجراءات، و`overlay` عند إبقاء المحتوى ظاهراً تحت طبقة التحميل. لا تنشئ مؤشراً أو إعلان وصول جديداً يدوياً.
- استخدم `PageLoadingState` عندما تحتاج Skeleton متخصصاً (`cards` أو `list` أو `detail` أو `table`)؛ أما المؤشر والرسالة فيبقيان من نظام التحميل المشترك.
- استخدم `LoadingGate` عندما تحتاج إلى تأخير إظهار مؤشر التحميل لتجنب الوميض في العمليات السريعة، مع إبقاء محتوى `fallback` واضحًا.
- استخدم `RouteLoadingState` في `app/loading.tsx` وفي جميع حدود مجموعات المسارات حتى يبقى شكل التحميل ورسائله موحداً. لا تحذف حدود `loading.tsx` كحل مفترض لمشكلة hydration دون اختبار قبل/بعد.
- يجب أن تكون حالات التحميل غير فارغة وقابلة للوصول، مع `role="status"` أو تسمية وصول مناسبة، وألا تعيد حدود الخطأ أو التحويل صفحة فارغة أثناء الاسترداد.
- لا تبدأ مؤشر تحميل صفحة عام عند تغيير query أو hash فقط إذا بقي `pathname` نفسه؛ استخدم حالة تحميل محلية عند الحاجة.
- أي مؤشر تنقّل عام يجب أن ينظف مؤقتاته ومستمعاته، وأن يمتلك مهلة أمان واستجابة واضحة للتنقّل المتعطل.
- احترم `prefers-reduced-motion`، ولا تجعل مؤشرات التحميل تعيق النقر أو التفاعل مع الصفحة.

## المكوّنات المشتركة

- `PageLoadingState`: هيكل تحميل صفحة/قسم مع رسالة وحالة وصول وخيارات `minimal` و`cards` و`list` و`detail` و`table`.
- `LoadingGate`: يعرض `fallback` أثناء التحميل وفق سياسة التأخير المشتركة.
- `LoadingState`: المصدر الموحد لعرض التحميل وإتاحة الوصول عبر الصفحة والقسم والإجراء والطبقة.
- `RouteLoadingState`: غلاف متوافق لحدود App Router يعتمد `LoadingState`.
- `LoadingSpinner`: غلاف توافق للمكونات القديمة؛ لا تضف تصميماً جديداً داخله.
- `NavigationProgress`: مؤشر انتقال عام مع مهلة أمان ورسالة استرداد عند تعطل الانتقال.

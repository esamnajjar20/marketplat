# المرحلة الثالثة — تقليل انتظار الخادم قبل إظهار الصفحة الرئيسية

## التغيير

- خُفّض الحد الأقصى لانتظار `prefetchHomeFeed` من 2500ms إلى 1200ms.
- يظل جلب `/home/static` المسبق مفعّلًا؛ إذا وصل ضمن المهلة تُضمّن بياناته في `HydrationBoundary` كما كان سابقًا.
- إذا تجاوز الطلب المهلة، لا يُمنع إخراج الصفحة إلى أجل غير محدد؛ ويستمر مسار العميل المعتاد في طلب الخلاصة بعد جاهزية المصادقة والمدينة.
- لم تتغير مفاتيح React Query أو شكل البيانات أو سياسة التخزين المؤقت أو ترتيب الأقسام أو نظام التحميل الكسول.
- لم يتم تفعيل أي نظام warming/preheating.

## لماذا هذا التغيير؟

كانت الصفحة تنتظر حتى 2.5 ثانية كحد أقصى قبل إكمال مكوّن الصفحة الخادمي. هذا حد انتظار مرتفع نسبيًا لطلب بيانات أولي؛ تقليصه يضع سقفًا أقل لتأخير إخراج هيكل الصفحة عندما يتباطأ المصدر.

## الأثر والمقايضة

- عند استجابة `/home/static` خلال 1.2 ثانية: لا يتغير مسار العرض المسبق.
- عند تجاوز 1.2 ثانية: قد يظهر هيكل الصفحة قبل توفر بيانات الخلاصة، ثم يجلب العميل البيانات عبر `/home/static` أو `/home/feed` حسب حالة تسجيل الدخول.
- هذا التغيير يحسن حد انتظار SSR فقط؛ لا توجد قياسات تشغيلية قبل/بعد تثبت تحسن زمن ظهور البيانات الفعلي أو LCP. ينبغي قياس TTFB ووقت ظهور أول بطاقة على شبكة بطيئة قبل ضبط المهلة نهائيًا.

## التحقق

أضيف `scripts/home-first-render-performance-audit.mjs` للتحقق من حد الانتظار، واستخدام المسار العام، وتطابق مفتاح الاستعلام بين الخادم والعميل، وبقاء hydration وشرط تفعيل الطلب.

شغّل: `npm run perf:home-first-render-audit`

لم يُشغّل اختبار Vitest أو `tsc --noEmit` أو بناء Next.js ضمن هذه المرحلة.

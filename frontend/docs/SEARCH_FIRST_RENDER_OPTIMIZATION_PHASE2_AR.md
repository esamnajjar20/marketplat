# المرحلة الثانية — تحسين أول ظهور لنتائج البحث

## المشكلة

مكوّن `SearchResults` يستخدم `useInfiniteQuery` بمفتاح يتغير مع كل فلتر/نوع/مدينة/ترتيب. عند تغير المفتاح، TanStack Query لا يعرض بيانات المفتاح السابق افتراضيًا، لذلك كان `isLoading` يعيد واجهة skeleton كاملة حتى لو كانت نتائج البحث السابقة ظاهرة قبل لحظة.

## الإصلاح

- إضافة `placeholderData: keepPreviousData` إلى استعلام البحث اللانهائي.
- إبقاء النتائج السابقة ظاهرة أثناء جلب نتائج الفلتر الجديد.
- تمرير `isPlaceholderData` إلى `ListDataStatus` ليظهر أن النتائج مؤقتة/قيد التحديث.
- إيقاف عرض أداة تحميل الصفحة التالية أثناء عرض بيانات مؤقتة، لمنع طلب صفحة إضافية اعتمادًا على بيانات الفلتر السابق.
- إضافة اختبار Regression لهذا السلوك.

## الأثر المتوقع

يقل زمن ظهور المحتوى المرئي عند التنقل بين فلاتر صفحة البحث؛ لا يتغير زمن استجابة API نفسه، ولا ندّعي تحسنًا رقميًا دون قياس متصفح بعد النشر. عند أول زيارة دون بيانات سابقة تبقى شاشة التحميل الأولية كما هي.

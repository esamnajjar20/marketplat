# تحسين أداء صفحة «خدماتي» — المرحلة الحالية

## قراءة سجل Network

الطلبات الثمانية المعروضة لا تثبت وجود ثمانية طلبات مكررة:

- `service-providers/me/dashboard?page=1&limit=10&period=all` يجمع مؤشرات النظرة العامة مع صفحة الخدمات.
- `service-listings/me` مع `status=ACTIVE` ثم `status=PAUSED` يمثل مجموعتي نتائج مختلفتين عند التنقل بين مرشحات الخدمات.
- `service-providers/me/analytics?period=7d` و`period=30d` مفتاحا كاش مختلفان لأنهما فترتان مختلفتان؛ ظهورهما متتاليتين يتفق مع تغيير الفترة في واجهة الإحصائيات.
- طلبا المواعيد والطلبات الواردة منفصلان وظيفيًا، وتبويباهما منفصلان عن النظرة العامة.

## التغيير

أُضيف فهرس مركب على `service_listings(providerId, status, createdAt, id)` لدعم قوائم مقدم الخدمة المفلترة والمرتبة بالأحدث، مع Prisma migration مستقلة. كما استُخدم `keepPreviousData` في استعلام إحصائيات مقدم الخدمة. عند تغيير الفترة، تبقى الأرقام السابقة ظاهرة مؤقتًا بدل استبدال لوحة الإحصائيات بالكامل بمؤشر تحميل. تظهر رسالة حالة واضحة أثناء جلب الفترة الجديدة، حتى لا يُفهم أن الأرقام القديمة تخص الفترة المختارة حديثًا.

لم يتم دمج فترات 7 أيام و30 يومًا في استعلام واحد؛ هذا يحتاج عقد API جديدًا من الباك إند، ولا يصح دمج نتائج بفترات مختلفة في الواجهة فقط. كما لم تُدمج قوائم ACTIVE وPAUSED لأنهما مجموعتا بيانات مختلفتان.

## ما لم يتغير

- تبويبات الطلبات والمواعيد والإحصائيات تبقى lazy حسب التبويب النشط.
- استعلام النظرة العامة يبقى مجمعًا للـ analytics + listings، ويُستخدم المفتاح نفسه في مكون الملخص ومكون قائمة الخدمات عند تطابق معاملات URL.
- لم تُعدّل صلاحيات أو حالات أو قواعد الترقيم. تتضمن الحزمة أيضًا Migration فهارس نشاط العملاء من المرحلة السابقة حتى يبقى `schema.prisma` متوافقًا عند تطبيق الحزمة على النسخة الأصلية. طبّق migrations عبر `prisma migrate deploy` بعد مراجعتها ونشر API؛ لن تُعاد migrations التي سبق تسجيلها كتطبيق ناجح.

## التحقق

شغّل من مجلد `frontend`:

```bash
node scripts/my-services-performance-phase-audit.mjs
npm run type-check
npx vitest run __tests__/components/MyServicesHub.test.tsx
```

لم تُشغّل اختبارات Vitest أو TypeScript الكامل في بيئة إعداد الحزمة الحالية لعدم توفر `node_modules`.

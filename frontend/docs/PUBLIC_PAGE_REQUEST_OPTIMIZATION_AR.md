# تحسين طلبات الصفحات العامة — 8 نوفمبر 2026

## ما أثبته سجل Network

- `GET /users/:id/profile-state` و`GET /blocked-users/:id/status` كانا يجلبان بيانات تُعرض في رأس الملف الشخصي نفسه. تم ضم `isBlockedByMe` إلى استجابة `profile-state` وإعادة استخدام استعلام React Query نفسه في زر الحظر. أصبح من المتوقع اختفاء طلب `blocked-users/:id/status` من فتح الملف الشخصي.
- `GET /service-listings/:id/matches` وطلب توصيات الخدمات كانا يُحمّلان أثناء فتح صفحة الخدمة. أصبح كل قسم مؤجلًا حتى الاقتراب من موضعه في الصفحة. لم ندمج المصدرين لأنهما مساران مختلفان وقد يعرضان مجموعتين مختلفتين.
- توصيات المنتجات في صفحة المنتج أصبحت مؤجلة حتى الاقتراب من القسم.
- قسم الإعلانات المشابهة كان يستخدم `LazySection` بالفعل؛ لا تغيير إضافي.

## ما أبقيناه عمدًا

- `GET /favorites/:type/:id/check`: مطلوب لمعرفة حالة القلب للمستخدم الحالي، ولا يجوز وضعه داخل استجابة تفاصيل عامة قابلة للكاش المشترك.
- `GET /products?storeId=...`: يغذي قسم منتجات المتجر نفسه، وهو مختلف عن توصيات متاجر أخرى.
- `PATCH /users/me/presence`: السجل يعرض طلبين بفاصل دقيقتين تمامًا؛ هذا يتوافق مع heartbeat الدوري وليس دليلًا على اشتراك مكرر.
- `GET /stories/feed` أو قصص الملف الشخصي: لا نلغيها دون مراجعة سلوك فتح القصص؛ قصص الملف الشخصي محملة عند الضغط على الصورة.
- طلبات `/search?type=...`: الأنواع الأربعة ظهرت في أوقات متقاربة، لكن السجل يجمع التنقلات ولا يحتوي Initiator؛ لذلك لا يمكن الجزم بأنها طلبات متزامنة من تحميل واحد.
- طلبات RSC مثل `?_rsc=` هي طلبات تنقل/عرض من Next.js وليست بديلًا عن طلبات API.

## طلب المحادثة 404

`POST /conversations` أعاد 404. من فرع المراسلة المباشرة بالملف الشخصي، يرجع 404 عندما لا يُعثر على المستخدم الهدف أو يكون غير نشط. أما سياق المنتج/الخدمة غير الصالح في هذا المسار فيُرجع 400، وليس 404. وإذا كان الطلب صادرًا من زر مراسلة إعلان فقد يكون الإعلان غير موجود أو محذوفًا. سجل Network لا يعرض جسم POST أو كود الخطأ الداخلي، لذلك لا يمكن تحديد الفرع الذي استُخدم من هذه اللقطة وحدها. لا نغيّر سلوك المراسلة اعتمادًا على تخمين.

## طلبات القوائم المتكررة

ظهر طلبان متطابقان ظاهريًا لقائمة المتاجر في رفح بفاصل 7 ثوانٍ. `useStores` يستخدم React Query ومدة stale مقدارها 90 ثانية؛ لذلك نحتاج Initiator وسجلًا يبدأ بعد Clear مع عدم تغيير المدينة/الفلاتر لتحديد هل السبب إعادة mount أو إبطال cache أو تنقل. لا نرفع مدة الكاش عشوائيًا.

## التحقق

شغّل من `frontend`: `node scripts/public-page-request-optimization-audit.mjs`. أضيف اختبار تكاملي للـ API يتحقق من أن حالة الحظر موجودة في `profile-state`. يجب تشغيل `npm run type-check` واختبارات API وVitest وبناء Cloudflare في بيئة المشروع قبل النشر.

# المرحلة الثالثة — اختبار الحمل المتدرّج والمستمر

## الهدف والنطاق

توسّع هذه المرحلة قياس المرحلة الثانية من تزامن أقصى 5 إلى مستويات `1, 5, 10, 25, 50`، ثم تنفذ اختباراً مستمراً لمدة تصل إلى خمس دقائق بمعدل محدد لا يتجاوز 10 طلبات في الثانية. كل طلب يصل إلى Worker المسبار المحمي وينفذ الاستعلام الثابت للقراءة فقط:

```sql
SELECT 1::int AS ok;
```

لا تغيّر هذه المرحلة Express أو Go أو Prisma أو إعداد Hyperdrive، ولا تنفذ عمليات كتابة أو CRUD. لا يلزم نشر Worker جديد؛ المرحلة الثالثة تستخدم الحقول التي أضافها Worker في المرحلة الثانية (`connectDurationMs` و`queryDurationMs` و`totalDurationMs`).

## حدود الحمل

| البند | الافتراضي | الحد الأقصى |
|---|---:|---:|
| مستويات التزامن | 1، 5، 10، 25، 50 | 50 طلباً متزامناً |
| الطلبات لكل مستوى | 60 | 100 |
| طلبات التسخين | 2 | 3 |
| مدة الاختبار المستمر | 300 ثانية | 300 ثانية |
| معدل الاختبار المستمر | 10 طلبات/ثانية | 10 طلبات/ثانية |
| الطلبات قيد التنفيذ في الاختبار المستمر | 10 | 10 |
| مهلة الطلب | 15 ثانية | ثابتة |
| إعادة المحاولة | لا توجد | لا توجد |

في التشغيل الافتراضي، الحد الأعلى النظري هو 300 طلب في مراحل التزامن، و3000 طلب في المرحلة المستمرة، وطلبان للتسخين؛ أي نحو 3302 طلباً. تعمل مستويات التزامن بالتتابع وليست مجتمعة. أما المرحلة المستمرة فتستخدم محدد معدل عام، وليس حلقة غير محدودة لإرسال أكبر عدد ممكن من الطلبات.

تتوقف الأداة عن تصعيد مستويات التزامن عند بلوغ حد الأخطاء (الأكبر من 3 أو 5% من محاولات المستوى). وفي المرحلة المستمرة تتوقف عن بدء طلبات جديدة عند بلوغ حد مماثل؛ وتنتظر انتهاء الطلبات التي بدأت بالفعل.

## المتطلبات

- Node.js ضمن المجال المحدد في `package.json` (`>=22.18 <25`).
- Worker المرحلة الثانية منشور ويعيد استجابة JSON التي تحتوي على `connectDurationMs`.
- رمز `HYPERDRIVE_PROBE_TOKEN` محفوظ في متغير بيئة محلي، ولا يرسل في المحادثة أو يحفظ في Git.
- `psql` واتصال Aiven متاحان لالتقاط إحصاءات الاتصالات يدوياً. هذه المراقبة منفصلة عن أداة HTTP.

تحقق من نسخة Node:

```bash
node --version
```

## الفحوصات قبل الاختبار

من مجلد `tools/hyperdrive-probe`:

```bash
npm ci
npm run check
npm run test:phase3
```

لا تنفذ `npm run deploy` لهذا التغيير؛ أداة المرحلة الثالثة عميل اختبار محلي ولا تغيّر Worker.

## إعداد المتغيرات

عيّن العنوان والرمز في جلسة الطرفية الحالية. أدخل الرمز دون طباعته:

```bash
export HYPERDRIVE_PROBE_URL='https://marketplat-hyperdrive-probe.esamnajjar6.workers.dev/__internal/db-probe'
read -rsp 'Worker token: ' HYPERDRIVE_PROBE_TOKEN
echo
export HYPERDRIVE_PROBE_TOKEN
```

لا تضع قيمة الرمز في ملف متعقب أو ترسله في المحادثة. لا تشارك `AIVEN_DATABASE_URL` أو كلمة مرور قاعدة البيانات أيضاً.

## التقاط اتصالات قاعدة البيانات

يحتوي `scripts/connection-snapshot.sql` على استعلام قراءة فقط يعرض عدد الاتصالات الحالي، والاتصالات النشطة والخاملة والخاملة داخل معاملة. لا يعرض نصوص الاستعلامات أو أسماء المستخدمين.

إذا كان متغير `AIVEN_DATABASE_URL` مضبوطاً محلياً، التقط لقطة قبل الاختبار:

```bash
psql "$AIVEN_DATABASE_URL" -X -v ON_ERROR_STOP=1 -f scripts/connection-snapshot.sql
```

افتح جلسة طرفية ثانية أثناء التشغيل، ونفّذ الأمر نفسه مرة أو مرتين لالتقاط العدد أثناء الحمل. بعد انتهاء benchmark التقط لقطة أخيرة. سجّل وقت كل لقطة والقيم الناتجة. جلسة `psql` نفسها تُحسب ضمن الاتصالات؛ لذلك لا تقارن الأرقام دون أخذ ذلك بالحسبان.

إذا لم يكن `psql` أو متغير الاتصال متاحاً، افتح `scripts/connection-snapshot.sql` في أداة SQL الخاصة بـ Aiven ونفّذ محتواه يدوياً. لا تلصق سلسلة الاتصال أو كلمة المرور في الطرفية الظاهرة أو في المحادثة.

## تنفيذ المرحلة الثالثة

من مجلد `tools/hyperdrive-probe`:

```bash
npm run benchmark:phase3
```

التشغيل الافتراضي ينفذ:

1. طلبَي تسخين.
2. 60 طلباً عند كل مستوى تزامن: 1 ثم 5 ثم 10 ثم 25 ثم 50.
3. إذا لم تتجاوز الأخطاء حد الإيقاف، اختباراً مستمراً لخمس دقائق بحد أقصى 10 طلبات في الثانية و10 طلبات قيد التنفيذ.
4. كتابة تقرير JSON محلي في `reports/phase3-<timestamp>.json`.

لتشغيل مرحلة التزامن فقط دون الاختبار المستمر:

```bash
PHASE3_ENABLE_SUSTAINED=false npm run benchmark:phase3
```

لتقصير التشغيل التجريبي مع الحفاظ على الحدود القصوى المدمجة:

```bash
PHASE3_REQUESTS_PER_LEVEL=20 \
PHASE3_SUSTAINED_DURATION_SECONDS=30 \
PHASE3_SUSTAINED_RPS=5 \
npm run benchmark:phase3
```

يمكن تخصيص مستويات التزامن أو الحدود ضمن النطاق المسموح، مثلاً:

```bash
PHASE3_CONCURRENCY_LEVELS=1,5,10,25,50 \
PHASE3_REQUESTS_PER_LEVEL=60 \
npm run benchmark:phase3
```

لا ترفع الحدود المدمجة ولا تعدّل ثوابت الأمان لمجرد الحصول على رقم أعلى. نفّذ الاختبار في فترة انخفاض الاستخدام، وراقب اتصالات Aiven أثناءه. أوقف التشغيل من الطرفية إذا ظهرت مؤشرات ضغط غير معتادة؛ لا تبدأ تشغيلات متزامنة متعددة.

بعد الانتهاء:

```bash
unset HYPERDRIVE_PROBE_TOKEN HYPERDRIVE_PROBE_URL
```

## تفسير التقرير

| الحقل | المعنى |
|---|---|
| `rampStages[].clientLatencyMs` | زمن HTTP من جهاز الاختبار حتى استلام الاستجابة كاملة |
| `workerConnectDurationMs` | زمن `client.connect()` عبر Hyperdrive |
| `workerQueryDurationMs` | زمن استعلام `SELECT 1` |
| `workerTotalDurationMs` | الزمن داخل Worker قبل تنظيف العميل |
| `maxObservedInFlight` | أعلى عدد طلبات كانت قيد التنفيذ فعلياً في المرحلة |
| `requestsPerSecond` | معدل الطلبات المكتمل/المحاولة ضمن نافذة القياس |
| `sustained.minuteBuckets` | عدد الطلبات والنجاحات والأخطاء لكل دقيقة |
| `targetRequestsPerSecond` | معدل بدء الطلبات المطلوب في الاختبار المستمر |
| `actualDurationIncludingDrainMs` | زمن الاختبار مع انتظار الطلبات التي بدأت قبل نهاية نافذة الحمل |

قارن `p50/p95/p99` مع عدد الاتصالات في Aiven. ارتفاع throughput وحده ليس معيار نجاح؛ راقب p95 والأخطاء واستقرار الاتصالات بعد انتهاء الحمل. قد لا يعكس `pg_stat_activity` كل التفاصيل إذا كانت صلاحيات دور قاعدة البيانات محدودة، بينما `pg_stat_database.numbackends` يعطي العدد الحالي للـ backends في قاعدة البيانات المحددة.

## شروط اعتبار النتائج صالحة للتحليل

- نجاح جميع طلبات التسخين.
- عدم وجود 401 أو أخطاء شبكة/مهلات غير مفسرة.
- عدم الوصول إلى حد الاتصالات أو موارد Aiven/Hyperdrive.
- عدم استمرار ارتفاع الاتصالات بعد توقف الحمل وفترة التنظيف.
- تسجيل لقطات الاتصالات قبل الحمل وأثناءه وبعده.
- إعادة القياس مرتين أو ثلاثاً في ظروف متقاربة قبل استخلاص نتيجة نهائية.

هذه المرحلة تقيس مسبار `SELECT 1` فقط. لا تثبت وحدها مقدار التحسن في تطبيق MarketPlat أو خفض اتصالات خدمات Express/Go. يلزم قبل الربط الإنتاجي اختبار استعلامات التطبيق الحقيقية ومراجعة توافق Prisma/Driver Adapter وخطة تراجع مستقلة.

## التراجع

لا تعدّل المرحلة الثالثة إعدادات Worker أو Hyperdrive أو قاعدة البيانات. لإيقاف الاختبار، أوقف العملية الجارية في الطرفية. أزل متغيرات البيئة بعد الانتهاء. تقارير JSON محلية ومستثناة من Git.
